
File: Config.nd
_______________________________________________________________________________

A file used to store information about the configuration as of last time a HTML output target was built.


Group: Format
_______________________________________________________________________________

	Topic: Header

		> [[Binary Header]]

		The file starts with the standard binary file header as managed by <CodeClear.NaturalDocs.Engine.BinaryFile>.


	Topic: Project Info

		> [String: Project Title or null]
		> [String: Project Subtitle or null]
		> [String: Project Copyright or null]
		> [String: Project Timestamp Code or null]
		> [String: Project Home Page Path (absolute) or null]
		> [String: Project Icon Path (absolute) or null]

		The project info as of the last run.  If any of the properties were not set they will be null.

		Project Home Page and Icon are the settings applied by <Project.txt>, if any.  It is not the final computed values
		that include any specified by styles.


	Topic: Style Info

		> [String: Style Path]
		>    (properties)
		> ...
		> [String: null]


		Stores the list of styles that apply to this target in the order in which they must be loaded.  Each one starts as
		a path, which is either to the style's CSS file or <Style.txt>.  These are stored instead of the names so that if a
		name is interpreted differently from one run to the next it will be detected.


		Style Properties:

			> [String: Style Path]
			>
			>    [String: Inherit]
			>    ...
			>    [String: null]
			>
			>    [String: OnLoad]
			>       [String: OnLoad After Substitutions]
			>       [Byte: Page Type]
			>       ...
			>    [String: null]
			>
			>    [String: Link]
			>       [Byte: Page Type]
			>    ...
			>    [String: null]
			>
			>    [String: Home Page Path (absolute) or null]
			>
			>    [String: Icon Path (absolute) or null]

			The properties are a null-terminated list of inherit statements, then a null-terminated list of OnLoad statements
			each followed by a page type byte, then a null terminated list of Link statements each followed by a page type
			byte.  There will not be a page type byte following the null strings that end the OnLoad and Link lists.

			Afterwards there's the paths to the custom home page file and icon files, or rull if they're not defined.


	Topic: File Source Info

		> [Int32: Source FileSource Number]
		>    (properties)
		> ...
		> [Int32: 0]
		>
		> [Int32: Image FileSource Number]
		>    (properties)
		> ...
		> [Int32: 0]

		Stores all the <FileSource> IDs and their properties.  This allows us to purge or rebuild the related output folders if
		one is deleted or changes.


		Source File Source Properties:

			> [Int32: Source FileSource Number]
			>    [String: Source FileSource UniqueIDString]
			>    [String: Source FileSource Name]
			>    [String: Repository Site Name]
			>    [String: Repository Project URL]
			>    [String: Repository Source URL Sample]

			The unique ID string allows us to identify the file source from one run to the next, even if its number changes.

			The repository source URL sample will be a link to a hypothetical source file and line number generated with the
			current repository settings.  Thus it would allow detection of any changes to the source URL template, the project
			URL, the branch name, and even the URL generation code in Natural Docs' own repository site templates.  The
			specific path and line number used are retrieved from <BinaryConfigParser.SampleRepositoryPath> and
			<BinaryConfigParser.SampleRepositoryLineNumber>.


		Image File Source Properties:

			> [Int32: Image FileSource Number]
			>    [String: Image FileSource UniqueIDString]

			The unique ID string allows us to identify the file source from one run to the next, even if its number changes.
